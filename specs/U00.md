# U00 · 数据在机器里的样子

出口能力：判断任意文件是文本还是二进制，用 hex 列出前 16 字节。
复用点：U10 U12 U20 U21 U23 U32
样本动作：7 个样本各列前 16 字节（动手题 U00.6-01）
新增概念：bit, byte, hex, offset, printable, ascii, utf8, text-vs-binary

## 节表

| 节 | 跑通物（读者敲完会看到什么） | 机制一句话 | 速查 | 题 |
| --- | --- | --- | --- | --- |
| 0.1 文件就是一串字节 | `file` 报 PNG，`xxd` 吐出 `8950 4e47 …IHDR` | 类型是读者从头部字节推断的，文件本身没有类型字段 | xxd 参数表 | U00.1-01 |
| 0.2 十六进制是二进制的缩写 | `printf 'A' \| xxd` 得 `41`；`\x41` 回来是 `A` | 16 = 2⁴，一位 hex 覆盖 4 位，一字节 = 2 位 | hex↔dec 0–15、常用字节值 | U00.2-01 |
| 0.3 ASCII 是一张约定表 | `printf 'Hello' \| xxd` 得 `48 65 6c 6c 6f` | 约定覆盖 00–7F；大小写差一位 0x20 | ASCII 区间表 | U00.3-01 |
| 0.4 UTF-8 与判据 | `len('你')=1` 而 `len('你'.encode())=3` | 变长，首字节高位模式决定长度 | 首字节模式表 | U00.4-01 |
| 5 自检 | — | 三道复查 | — | U00.5-01..03 |
| 6 动手 | — | 给 7 个样本建档 | — | U00.6-01 |

## 明确不教

- 字节序（大端/小端）——第一次真正用到是在 U12 读 PNG 的宽高，放那里
- UTF-8 续字节的位级规则——本课只需要「首字节定长度」
- 位运算——U07 专章
- PNG chunk 结构——U21

## 实测记录

环境：WSL Ubuntu-24.04，`xxd 2021-10-22`，`python3 3.12`。

| 命令 | 实跑输出 | 与正文一致 |
| --- | --- | --- |
| `file samples/S-01.png` | `PNG image data, 64 x 64, 8-bit/color RGB, non-interlaced` | 是 |
| `xxd -l 16 samples/S-01.png` | `00000000: 8950 4e47 0d0a 1a0a 0000 000d 4948 4452  .PNG........IHDR` | 是 |
| `file samples/S-04.gz` | `OpenPGP Public Key` | 是（正文用它演示 file 会看错） |
| `printf 'A' \| xxd` | `00000000: 41 … A` | 是 |
| `printf '\xe4\xbd\xa0' \| xxd` | `00000000: e4bd a0  ...` | 是 |
| `python3 -c "print(len('你'), len('你'.encode()))"` | `1 3` | 是 |
| `xxd -s 32 -l 3 -p samples/S-04.gz` | `1f8b08` | 是 |
| `python3 -c "print(chr(ord('A')|0x20), chr(ord('a')&~0x20))"` | `a A` | 是 |

样本本身由 `scripts/build-corpus.py` 确定性生成，`scripts/verify-corpus.py` 的 20 项断言全过。
