# 教学大纲 v4 · 对标 C++ Primer

> 目标态。`01-course-map.md` 只记完成度，冲突时以本文档为准。
> v3 的错误：单元太大（80–140 分钟），无法「一节节产出」。v4 引入**节**作为交付原子。

## 0. 对标说明（不是口号，逐条对上）

| C++ Primer / C Primer Plus 的结构 | 本课程 |

## 1. 结业标准

| # | 场景 | 通过线 |
| --- | --- | --- |
| C1 | 一道网上搜不到题解的 misc/编码题 | 30 分钟内走完识别 → 提取 → 得 flag，不查资料 |

## 2. 两条路径

| 路径 | 包含 | 达标 | 学时 |
| --- | --- | --- | --- |
| **最小路径** | Part 0 → 1 → 2 → 3 的前 3 章 → Part 5 | C1, C2 | ≈ 45 h |
| **完整路径** | 全部 7 个 Part | C1–C4 | ≈ 67 h |

C++ Primer 明说 Part I 必读、其他可跳。这里同理：Part 4（网络）、Part 6（线索链）是完整路径专属，但它们决定 C3/C4 能不能过。

## 3. 三层结构与每节的四件套

```
Part（能力阶层） → 章 = 单元（验收单位） → 节（交付原子，15–25 分钟）
```

**每一节固定四件套**（缺一件不算完成）：

| 件 | 要求 |
| --- | --- |
| **跑通物** | 一条能跑的完整会话（输入 + 输出），本节以一个具体结果开场 |
| **机制** | 这个结果为什么是这样，推导不跳步 |
| **速查** | 本节用到的表，就地给（没有就写「本节无新表」） |
| **题** | 1–2 题，编号 `<章>.<节>-<序号>`，带折叠提示与答案 |

**章（单元）额外两件**：章首 3 条「读完能做什么」、章末术语表 + 自检 3 题 + 动手 1–2 个。

**三种标记块**（inline，替代笼统的「常见错误」）：

```
> **易错**　这里 90% 的人会写成 XX，报错是 `YY`
> **约定**　业界默认这样做，不是硬性规定
> **实践**　实战里建议固定这个动作，能省时间
```

## 4. 设计原则

1. **先跑通再解释**：每节第一段是一个可执行的结果，不是定义。
2. **节可独立停下**：读完一节，手上有一套完整动作，下一节不解释它也能开始。
3. **螺旋**：同一个 5 步循环跑 7 遍，每遍换域、每遍更长。
4. **贯穿样本**：一批永不改动的文件从 Part 0 用到 Part 6，替代「记得前面学过」。
5. **零搜索依赖**：表就地给。
6. **原理优先**：给机制，不用比喻。
7. **零基础假设**：每条命令给完整会话。
8. **两层练习**：自检（概念，可机验）+ 动手（交东西）。
9. **复用门槛**：章必须被 ≥3 处后续复用，否则降为章末速查表。

## 5. 方法线（Part 0 之前，第 1 周就要有）

| ID | 内容 | 时长 |
| --- | --- | --- |
| **M0** | 5 步循环 + paper trail 模板 | 60 |

| 步 | 动作 | 新手在此崩掉 |
| --- | --- | --- |
| S1 侦察 | 枚举这道题有几层、每层有什么信号 | 直接跳到「我猜是 Base64」 |
| S2 假设 | 由信号生成**可判伪**的候选 | 生成不可判伪的假设 |
| S3 排序 | 按成本/信息量排试验顺序 | 按「我想得到的顺序」试 |
| S4 判伪 | 一步能否掉 | 试不动就加努力，不换假设 |
| S5 外存 | 写下来、设放弃点、切换 | 靠脑子扛状态，重复走过的路 |

专家与新手差的不是知识量，是 S2 的可判伪性、S3 的成本感、S5 的外存纪律。
**所以「提前 PH」不是把题型提前，是把方法线提前。**

## 10. 不教什么

| 不做 | 理由 |
| --- | --- |
| 团队协作、分工、沟通 | 用户明确单人 |
| 0day、真实目标渗透、免杀 | 越界且与解题无关 |
| 编译原理级逆向 | 只到「能定位校验逻辑」 |
| 硬件、无线电、单片机 | 需实物，产出比低 |
| 转载题库原文 | 只链接 + 自写解法 |

**待定池**（不进主线）：Pwn 入门、内存取证、无线与 USB、二维码纠错、盲水印、分组密码模式、Web 进阶（SSTI/反序列化）、自制 ARG。
