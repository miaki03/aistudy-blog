# 单章生产工作流 v3

> 对标 C++ Primer 的写作单元：**节是交付原子**，章是验收单位，Part 是评审单位。
> v2 的问题：以「章」为单位规划和评审，太重，且没法一节节交付。

## 1. 三级节奏

| 级 | 单位 | 产出 | 评审 |
| --- | --- | --- | --- |
| **节** | 15–25 分钟 | 一节正文（跑通物 / 机制 / 速查 / 题）+ 题号登记 | 自查，不对外 |
| **章**（单元） | 3–5 节 | 章首 3 条目标、章末术语表 + 自检 + 动手 | `check.py` 全绿 + 提交 |
| **Part** | 3–5 章 + 1 项目 | 项目交付物 | **一次独立子代理评审 + 用户验收** |

评审从 26 次降到 7 次。章级只跑脚本，人眼留到 Part 级——**因为 Part 级的项目会把前面章的漏洞一次性暴露出来**（这是项目当回归测试的第二个用途）。

## 2. 开写前的 5 分钟：节表

不写 40 行契约了。写一张节表，放在 `specs/<章ID>.md` 顶部：

```markdown
# U00 · 数据在机器里的样子
出口能力：判断任意文件是文本还是二进制，用 hex 列出前 16 字节
复用点：U10 U12 U20 U21 U23 U32
样本动作：7 个样本各列前 16 字节

| 节 | 跑通物（读者敲完会看到什么） | 机制一句话 | 速查 | 题 |
| --- | --- | --- | --- | --- |
| 0.1 | `file` 说 S-01 是 PNG，`xxd` 吐出 8950 4e47 | 文件就是字节序列，扩展名不是数据 | — | U00.1-01 |
| 0.2 | `printf 'A'` 得 41 | 一位十六进制 = 4 位二进制 | hex↔十进制 0–15 | U00.1-02 |
| 0.3 | `xxd` 右侧出现 `Hello` | 可打印字节是 ASCII 约定 | ASCII 关键区间 | U00.2-01 |
| 0.4 | 中文一字节数 ≠ 字数 | UTF-8 是变长 | 常见编码长度 | U00.3-01 |
```

**节表就是漂移的检查点**：写的时候如果某一节的"跑通物"想不出来，说明这一节没有可教的动作，要么删要么并。**这一步 5 分钟，能省一次返工。**

## 3. 逐节写作的四件套

每节严格按这四块，顺序固定：

| 块 | 写法 | 反例 |
| --- | --- | --- |
| **跑通物** | 一个完整会话：`$` 提示符 + 命令 + 真实输出。读者第一节就能跑出结果 | 先讲三段定义再给命令 |
| **机制** | 这个结果为什么这样，推导不跳步，不用比喻 | 「就像翻译一样」 |
| **速查** | 本节用到的表就地给，没有就写「本节无新表」 | 指向文末附录 |
| **题** | 1–2 题，编号 `<章>.<节>-<序号>`，折叠提示 + 折叠答案 | 章末一次性堆 6 题 |

三种 inline 标记（替代笼统的「常见错误」节）：

```
> **易错**　90% 的人会写成 X，报错原文是 `Y`
> **约定**　业界默认，不是硬性规定
> **实践**　实战里建议固定这个动作
```

## 4. 章收尾（4 件事）

1. **章首 3 条「读完能做什么」**（动词开头，可测）
2. **章末术语表**（本节的术语集中，不集中到附录）
3. **章末自检 3 题 + 动手 1–2 个**（两层练习）
4. **复用登记**：本章被哪 ≥3 处后续引用，写进 `kb/concepts.json`

## 5. 校验：一个脚本，随用生长

```bash
python3 scripts/check.py
```

它检查什么，取决于已经写到哪：

| 写到 | 加上的检查 |
| --- | --- |
| U00 | 概念是否在 `concepts.json` 登记；章节 front matter 字段齐全 |
| U10 | `problems` 与 `problems.json` 双向一致；每条 `verify` 跑通 |
| U21 | 复用点 ≥3 |
| P1 | 项目覆盖：每个 Part 0 的章都被 P1 引用 |
| Part 2 | 贯穿样本文档里每个样本至少被一个 Part 的动作表提到 |

不预留检查项。**没用例就不写检查**——这就是上一版 4 个脚本过度设计的原因。

## 6. 防漂移的 6 条结构约束

| # | 机制 |
| --- | --- |
| 1 | **节表前置**：写不出来「跑通物」的节就不该存在 |
| 2 | **概念台账** `kb/concepts.json`：新章只能引用已定义概念，或自己定义并登记 |
| 3 | **语义冻结**：已提交章的定义不改，只追加；要改必须记变更并列受影响章 |
| 4 | **复用门槛**：章 ≥3 处复用，否则降为章末速查 |
| 5 | **贯穿样本**：新 Part 若推翻旧 Part 结论，立即暴露 |
| 6 | **项目即回归测试**：Part 末项目做不出 = 该 Part 设计有问题，回头改，不往前写 |

## 7. DoD（6 项，全勾才算一章完成）

- [ ] 1. 节表存在，每节的跑通物都被实测过
- [ ] 2. 章首 3 条目标 + 章末术语表 + 自检 3 + 动手 1–2
- [ ] 3. 每条命令给完整会话（输入 + 输出 + 报错怎么读）
- [ ] 4. 题号 `<章>.<节>-<序号>`，`problems.json` 双向一致
- [ ] 5. `check.py` 绿；文中每条命令能粘贴即跑
- [ ] 6. 复用点 ≥3 已登记

## 8. 提交粒度

- **一节一 commit**：`feat(U00.2): hex 与二进制`
- **一章一 push**：推送时跑一次 `hugo -D --gc --minify`，确认路由
- **一个 Part 一次评审**

用户可以在 git log 里按节看进度，这比"又写完一章"更有节奏感。

## 9. 已知失败模式

| 失败模式 | 已发生 | 谁拦 |
| --- | --- | --- |
| 前置指向不存在的章 | S-B64 → S-BIN | 节表第 1 条（复用点要写具体章） |
| 引用不存在的题号 | P1 引用了 P1-01..06 | `check.py` |
| 断言靠猜（报错原文、字节数） | `b64decode('-_8=')` 的真实报错 | 跑通物必须实测 |
| 比喻代替解释 | 「地盘」「替身」「万能钥匙」 | 禁用词检查 |
| 讲一堆没练习 | 初版 Base64 只有 2 题 | 节级题号，一节必有题 |
| 常识当课上 | v2 的 S-PH-KNOW | 复用门槛 |
| 章太大没法交付 | v3 的 140 分钟单元 | 节 = 15–25 分钟 |
