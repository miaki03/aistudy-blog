# 决策记录

按时间倒序。每条写「决定了什么 / 为什么 / 代价」。

## D-16 推送改为批量，只在 Part 边界

- **为什么**：Cloudflare Pages 免费版按构建次数计，每次推送都触发一次；逐章推送会把额度耗在中间状态上，影响日后正常更新。
- **代价**：线上会比本地滞后一个 Part（3–5 章）。commit 仍按节/章，git log 里的进度不受影响。

## D-15 抽出一份学科无关的 `docs/PLAYBOOK.md`

- **为什么**：这套「Part/章/节 + 贯穿样本 + 概念台账 + 可验证题」的方法与 ARG/CTF 无关，换成高数、语言、乐理同样成立。写死在本仓库的 `07`/`08` 里，下次做别的主题要重写一遍。
- **代价**：`PLAYBOOK.md` 与 `07`/`08` 有部分重叠。约定：**PLAYBOOK 讲通用方法，07/08 只讲本学科的具体填充**；冲突时以 PLAYBOOK 为准。

## D-14 按零基础设计

- **为什么**：用户明确「就当零基础，没系统性学过」。
- **代价**：加整个 Part 0（5 章 22 节，9.5 h）；「完整会话」从建议变成硬规则；入口自测改作 U04 的出口检查。

## D-13 引入「节」作为交付原子（对标 C++ Primer）

- **为什么**：v3 的单元 80–140 分钟，无法「一节节产出」；C++ Primer 以 2–5 页的节为学习原子。
- **代价**：26 章拆成 103 节，管理粒度变细；好处是每节都能独立交付和验证，题号绑定节号。

## D-12 贯穿样本集替代「记得前面学过」

- **为什么**：C++ Primer 靠 `Sales_item` 反复出现防脱节。口头约定「复用点」不构成机制。
- **代价**：要先建 `samples/corpus/` 的 7 个文件；好处是漂移会被新 Part 自动暴露。

## D-11 取消全局附录，速查表附着到节末

- **为什么**：C++ Primer 的表放在第一次用它的那一页；集中附录等于让读者先背再看。全局附录只留 3 个（术语对照、工具参数、报错）。
- **代价**：同一张表可能被多节各自给一次，需在概念台账里去重。

## D-10 章必须被 ≥3 处后续复用，否则降为速查表

- **为什么**：这是「不堆积知识」的可执行判据。不能复用的知识说明它不参与解题。
- **代价**：v3 大纲 50 页里有 20 多页因此被砍或降级。

## D-09 技能页用 `draft = true` 交付

- **为什么**：用户要审阅后再发布；草稿不进 `public/`，线上站不受影响。
- **代价**：需要在 `hugo -D` 下才能预览；发布前要逐页改 `draft = false`。

## D-08 题库用 JSON 而非 YAML

- **为什么**：`check-kb.py` 只依赖标准库（`json` + `tomllib`），不引入 PyYAML；WSL 里没装。
- **代价**：人工编辑时没有 YAML 的注释和多行字符串便利，已在 `kb/README.md` 说明字段。

## D-07 题目分「机器可验证」与「人工证据」两类

- **为什么**：编码/解码类题可以跑命令比对答案；文件类型判断题无法自动化，但可以要求写出可核对的事实。
- **代价**：`manual` 题的质量取决于 `evidence` 写得够不够具体。

## D-06 不转载题面，只链接 + 自写解法

- **原因**：版权归原作者；档案站改版会让单题链接漂移；而解法比题面更有教学价值。
- **代价**：读者需要点出去看题面（但解法、提示、复盘都在站内）。

## D-05 先技能页后项目页

- **原因**：用户指出「没有积累就做不动项目」，所以顺序必须是「先学单元、再挑精确匹配的题、最后用项目串联」。
- **代价**：早期上线的内容偏「零散知识点」，缺少成就感；靠项目页补。

## D-04 URL 用 `/s/` 与 `/proj/` 前缀

- **原因**：与旧文章的 `/p/` 区分，便于以后按类型做索引页。
- **代价**：`hugo.toml` 多两条 permalink 规则。

## D-03 课程不用固定 8 模块，而用「技能 + 依赖」

- **原因**：旧 8 篇是课程表气质；用户要的是「学完 X 立刻做 X 的题」。依赖图能自动排出顺序。
- **代价**：需要一个课程地图文档维护依赖与覆盖。

## D-02 站点独立成 `aistudy-blog` 仓库

- **原因**：用户要求与个人博客 `miaki-blog` 分开。
- **代价**：主题用子模块锁定在 `2f8b1be`（与博客同一 commit），保证渲染一致。

## D-01 技术栈 Hugo + Stack，不换 docs 主题

- **原因**：已部署、渲染稳定，换主题要重配，和「少在形式上花精力」冲突。
- **代价**：没有原生侧边栏导航，需要后续自己加索引页。
