# Part 级评审清单

> 章级只跑 `check.py`（见 `08-chapter-pipeline.md` §7 的 6 项 DoD）。
> **本文档是 Part 级评审用的**，一个 Part 用一次，共 7 次。

## A. 跨章一致性

- [ ] 同一个概念在不同章里的定义一致（对照 `kb/concepts.json`）
- [ ] 前面章承诺的动作，后面章真的用上了（复用点可查）
- [ ] 没有两章重复讲同一件事（重复 = 其中一章该降为速查）
- [ ] 章与章的难度是台阶，不是断崖

## B. 贯穿样本

- [ ] 本 Part 的样本动作已写入 `samples/` 的档案
- [ ] 新结论没有推翻旧 Part 的结论；若推翻了，旧章已修
- [ ] 样本仍未被改动（`scripts/build-corpus.py` 可重算出同一批文件）

## C. 能力达成（对照 `07-syllabus.md` §1）

- [ ] 本 Part 的「出口能力」真的能测：随便挑一条，现在能做出来
- [ ] 如果做不到，是缺章还是章写坏了？记下结论

## D. 项目可做性

- [ ] 项目所需的每一章都已完成，没有隐形前置
- [ ] 项目有明确交付物与时间上限
- [ ] 项目做不出来时会暴露哪个章的问题（回归测试有效性）

## E. 保姆级（抽 3 节做粘贴即跑）

- [ ] 命令完整，输出与文中一致
- [ ] 术语首次出现当场定义
- [ ] 没有要求读者自行搜索
- [ ] 没有禁用比喻
- [ ] 报错原文是实测的，不是构造的

## F. 题与答案

- [ ] 题号符合 `<章>.<节>-<序号>`
- [ ] 每题有折叠提示与折叠答案
- [ ] 机器可验的题有 `verify` 且能跑通
- [ ] 有一道反方向的题（编码 ↔ 解码、识别 ↔ 排除）

## G. 工程

- [ ] `python3 scripts/check.py` 全绿
- [ ] `hugo -D --gc --minify` 构建通过，路由正确
- [ ] `draft` 状态经用户确认
- [ ] 本 Part 的章都已 push
