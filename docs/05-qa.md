# 每页验收清单

一页写完后逐条打勾。**不过清单不算完成。**

## A. 内容正确性

- [ ] 所有举例都用命令实跑过，输出与正文一致
- [ ] 每个断言都能复现或引用到出处（RFC、手册页、官方文档）
- [ ] 公式给出，并有至少 2 组实测数据核对
- [ ] 手算示例的每一步都能和命令输出对上
- [ ] 边界情况覆盖：空输入、长度模数为 1、缺 padding、大小写

## B. 保姆级标准

- [ ] 正文用到的每个概念都在首次出现时定义
- [ ] 没有要求读者「自行搜索」的地方
- [ ] 命令给完整（含参数），输出给完整
- [ ] 环境差异已说明（GNU / BSD / Windows）
- [ ] 正向与反向都有示例

## C. 风格

- [ ] 没有禁用比喻（见 `02-style-guide.md` 禁用表）
- [ ] 没有「显然」「众所周知」
- [ ] 每段先说「这段解决什么」，不是命令堆砌
- [ ] 术语表完整

## D. 练习与答案

- [ ] 3–5 题，难度递进
- [ ] 每题都有 `<details>` 提示与答案
- [ ] 答案附可复跑命令
- [ ] 题号已登记到 `kb/problems.json`
- [ ] 机器可验证的题有 `verify`；人工题有具体 `evidence`

## E. 工程

- [ ] front matter 字段完整（chapter / stage / minutes / prereq / skills / problems）
- [ ] `python3 scripts/check-kb.py` 通过
- [ ] `hugo -D --gc --minify` 构建无警告
- [ ] 内部链接可点（`/s/`、`/proj/`、`/p/`）
- [ ] 发布前 `draft` 状态经用户确认

## F. 外部评审补充项（Base64 页暴露的）

- [ ] 承诺的能力（如「能手算」）在正文里真的教了
- [ ] 识别表写成「候选/排查」，不是判定规则
- [ ] 报错解释与实测一致，不写未验证的「通常会报 X」
- [ ] 长度/体积类结论有公式支撑
