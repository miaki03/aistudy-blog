# 读者卡点库

> 从真实复验里沉淀的检查清单。**写作前先过一遍，写完后自己对照一遍**——目标是把复验从"发现 15 条"压到"发现 3 条以内"。
> 每条都来自实际卡点，不是想象出来的。

## 0. 复验循环规则（防钻牛角尖）

- 同一章**最多复验 3 轮**；
- 第 3 轮仍有卡点 → **算通过**，把剩余卡点记进 `specs/<章>.md` 的「已知卡点」；
- 理由：3 轮还过不去，通常是复验方在按自己的知识结构挑刺，不是读者真的会卡。继续追会消耗在幻觉上，收益为负。

## 1. 环境入口：读者不知道自己有什么

**卡点**：「开始菜单搜 Ubuntu（WSL）」——没装 WSL 的人根本没有这个应用，而后面所有命令都依赖这个前提。

| 规则 | 写法 |
| --- | --- |
| 给**判断方法**，不只给名字 | 「在开始菜单里搜 `Ubuntu`：能搜到就打开它；搜不到说明没装，走下面的替代方案」 |
| 给**降级路径** | 首选之外，至少给一条"没有这个东西时"怎么办 |
| 说明**为什么必须用它** | 「PowerShell 里没有 `xxd`，所以本章要在 WSL 里做」 |

## 2. 相对路径：读者不知道自己站在哪

**卡点**：正文里全是 `static/samples/S-01.png`，但没有任何一条命令告诉读者怎么走到那个目录。

| 规则 | 写法 |
| --- | --- |
| 每个路径第一次出现时，给出**从哪一层开始**的说明 | 「以下命令都在仓库根目录执行（`pwd` 会显示 `.../learning-path-site`）」 |
| 需要换目录时，给**那一条 `cd`** | 不要假设读者已经在那里 |
| 临时路径要解释它是什么 | 「`/tmp` 是 Linux 的临时目录，重启会清空，随便写」 |

## 3. 断言没有出处：读者只能「信」

**卡点**：正文说「`50` 是 `P`，`4e` 是 `N`」，但不给规则——读者无法验证，只能信。同类：`00000010` 就是 16。

| 规则 | 写法 |
| --- | --- |
| **能给的规则必须给**，哪怕只给一句 | 「ASCII 规定 `0x50` 对应大写 `P`，完整规则在 U02」 |
| 留给后章的，必须给**此刻的具体读法** | 不写「为什么是十六进制属于 U01」，而写「`00000010` 里最后两位是 `10`，前面的 0 只是占位，读到 `16` 就够用」 |
| 只允许"信"，不允许"猜" | 差别：信 = 作者明确说"这里先接受这个结论"；猜 = 作者以为自己讲清了 |

## 4. 计数类断言必须实测

**卡点**：「那 9 个点是 9 个不同的字节」——实际同一行里 `0d` 出现两次、`0a` 两次、`00` 三次，读者一数就对不上。

| 规则 | 写法 |
| --- | --- |
| 任何「几个」「恰好」「都是」的断言，**写之前数一遍** | 用脚本数，不要凭视觉 |
| 数不对时改说法，不改事实 | 把「9 个不同的字节」改成「9 个显示不出来的字节」 |

## 5. 题目不能引入正文没教过的命令

**卡点**：题目的提示让读者用 `wc`、用 `<`，而 `wc` 全文没出现过，重定向说"到 U04 讲"。

| 规则 | 写法 |
| --- | --- |
| 题**只用本章教过的命令** | 要引入新命令，就在正文补一小节，或换题 |
| 允许"下一章会讲"的**概念**，不允许"下一章会讲"的**必需操作** | 操作是必须当场能用的 |

## 6. 工具输出里的术语必须处理

**卡点**：`file` 输出里的「每像素 8 位 RGB 三色，非隔行」——四个术语（位/RGB/像素/隔行）都没定义。

| 规则 | 写法 |
| --- | --- |
| 引用工具输出时，逐项决定：**解释 / 标"暂时忽略"** | 「`64 x 64` 是宽高；后面那句 `8-bit/color RGB` 本章用不到，忽略」 |
| 不许留白 | 读者会把不了解的东西当成"我漏了什么" |

## 7. 练习站指引必须能直接照做

**卡点**：让英文弱的读者「去 Bandit 打 0–5 关」，还让他「照抄网站首页那行 ssh」——这本身就是一次跳出去查。

| 规则 | 写法 |
| --- | --- |
| 给**怎么进去**：哪一行、抄哪里、粘到哪 | 不要只说"网站首页写着" |
| 明确**允许跳过**：「卡住就跳过，本章只要求把这几个命令用熟」 |
| 补**中文解释**：练习站只给线索 | 把关键提示的英文原句引出来并翻一句 |
| 不要把练习站当前置 | 它是**加分项**，不是本章通过条件 |

## 8. 报错要覆盖「命令不存在」

**卡点**：只教了 `No such file or directory` 与 `Permission denied`，但读者最可能遇到的是 `command not found`。

| 常见报错 | 一句话解释 |
| --- | --- |
| `No such file or directory` | 路径写错（拼错、少一层、大小写） |
| `Permission denied` | 权限不够，不是路径错 |
| `command not found` | 这条命令没装，或拼错了命令名 |
| `Is a directory` | 你给的是目录，不是文件 |

## 9. 分组与计数描述要防歧义

**卡点**：「每两个字符是一个字节，8 个一组」——读者不知道"8 个"指字符还是字节，而输出里视觉上是 4 字符一组。

| 规则 | 写法 |
| --- | --- |
| 数字后面必须跟**单位** | 「每 8 个字节（视觉上一组 4 组、每组 4 个字符）」 |
| 最好给**对齐示例** | 把一行拆成两组来展示间隔 |

## 10. 否定句要说清否定什么

**卡点**：「文件不存『字』」——读者不知道这句在反驳谁的什么说法。

| 规则 | 写法 |
| --- | --- |
| 否定句补全对象 | 「文件里存的不是『字符』，而是字节；字符是你用某个编码读出来的结果」 |

## 11. 延伸里的东西也要能读

**卡点**：推荐「`man xxd`」，但读者不知道 `man` 是什么，而且那必然是满屏英文。

| 规则 | 写法 |
| --- | --- |
| 推荐英文-only 的手段时要标注 | 「输出是英文，只看开头第一段（NAME 和 SYNOPSIS）就够」 |
| 不给无法消化的推荐 | 宁可换成"表已在本节给全" |

## 12. 写完后自己跑一遍这个检查表

按顺序问：

1. 读者知道**在哪个窗口**敲第一行吗？
2. 读者知道**站在哪个目录**吗？
3. 每个「A 等于 B」的断言，有没有出处或读法？
4. 所有「几个」「都是」我都数过吗？
5. 题目只用本章教过的命令吗？
6. 工具输出里的每个术语都处理过吗（解释或标忽略）？
7. 练习站指引能直接照做吗？允许跳过吗？
8. 报错覆盖了 `command not found` 吗？
9. 数字都带单位吗？
10. 否定句都说清否定什么了吗？
11. 延伸里的推荐读者能消化吗？
