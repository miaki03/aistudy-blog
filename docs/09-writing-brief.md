# 写作包规范（最小充分上下文）

> 给写正文的那个 agent 看的。目的是**把会话史挡在写作工作区之外**，而不是把眼睛蒙上。
> 上下文少 ≠ 信息少。给的是必要的结构信息，去的是我们这一路的讨论、取舍、旧版本。

## 0. 为什么需要这一层

作者如果带着「整段对话记忆」写，会稳定地犯四个错：

| 错 | 表现 |
| --- | --- |
| 跳步 | 「这正是前面讲过的字节数 ≠ 字符数」——作者记得，读者不记得 |
| 用内部坐标 | 「这是 Part 2 的内容」「W5 再学」——那是进度表，不是读者的坐标系 |
| 替读者补全 | 「显然要先 xxd 再 cat」——作者知道后果，读者不知道 |
| 用历史当理由 | 「上一版这里做错过，所以……」——读者没有那个上一版 |

反过来，**只给一个空洞题目也不行**：写作 agent 不知道前后有什么章、不知道哪些概念已经定义过，就会自己发明顺序、重复讲别章的内容、把后面的坑提前踩。**那比跳步更严重。**

所以：**给全「计划与位置」，不给「历史与讨论」。**

## 1. 写作包必须包含的 12 项

| # | 项 | 要求 |
| --- | --- | --- |
| 1 | **书籍定位与读者画像** | 一段话：这是什么教材、给谁、读者现有的基础边界（例如「会用电脑、没受过 CS 系统训练」）、外部约束（单人、不查外网、中文母语但英文弱） |
| 2 | **全局大纲** | 全部 Part 与章清单，每章一句目标。**必须给**，否则会重复别章内容或把后面章节的坑提前踩 |
| 3 | **本章位置** | 读者读到这里已经会什么：列出前置章号 + 已定义概念清单（取自 `kb/concepts.json`） |
| 4 | **本章唯一目标** | 一句话，可测。形式：「给定 X，能做出 Y」。不允许「理解 Z」 |
| 5 | **节表 + 实测跑通物** | 每节一行：锚点结果（命令 + **真实输出**，由校验方跑过）+ 机制一句话 + 速查内容 + 题号 |
| 6 | **风格规范全文** | 照抄 `docs/02-style-guide.md`，不要摘要 |
| 7 | **概念边界** | 可引用的概念（已定义）+ 本章允许新增的概念。新增的要给 id / 中文 / 英文 |
| 8 | **明确不教** | 列出容易顺手写进来的邻近主题，并指明它们属于哪一章 |
| 9 | **题目与 verify** | 题目正文的**考点**、编号、机验方式由校验方提供。写作方负责写题面、折叠提示、折叠答案 |
| 10 | **篇幅参考** | 给字数区间，并注明**这是参考不是门槛**（见 §4） |
| 11 | **交付格式** | front matter 模板，字段名与取值必须照抄 |
| 12 | **交稿自查** | 要求它逐节回答「读者在这一段可能卡在哪」，并列出自己**拿不准**的地方 |

## 2. 明确不给的

- 我们讨论过哪些方案、为什么砍掉某个方案
- 旧版本长什么样、改过几轮
- 其他章的正文、写作风格演化过程
- 用户的偏好是怎么一步步形成的
- 任何进度元话语（「Part 2 会讲」「这套课后面会」）

**判据**：一段信息如果只解释「为什么变成现在这样」，而不影响「这一章要写成什么样」，就不给。

## 3. 三方分工

| 角色 | 谁 | 输入 | 产出 |
| --- | --- | --- | --- |
| **校验方** | 主 agent | 全部上下文 | 写作包、实测数据、题库与 verify、审核、发布 |
| **写作方** | 子 agent（按写作包） | 只有写作包 12 项 | 正文草稿 + 交稿自查 |
| **复验方** | 另一个子 agent（独立） | **只有读者画像 + 正文**（不给写作包、不给大纲） | 卡点清单 |

写作方知道计划但不知道历史；复验方**什么都不知道，只有正文**——它是最接近真实读者的那个。

## 4. 篇幅：参考值，不是门槛

字数区间的作用是**预警**，不是硬拆依据。

> 就像设计函数：不能因为一条必要的代码让函数超过 30 行，就把它硬拆成两个函数。拆开的代价是读者要在两个地方拼回一个概念。

规则：

- 超过区间上限时，**不自动拆章**，先问「这段超出是不是必要」；
- 必要时保留，并在 `specs/<章>.md` 写明超出理由；
- 不必要时才砍——砍的优先顺序是：删元话语 > 删重复示例 > 删铺垫 > 合并节。

反过来，低于下限也要警惕：可能是该讲清的机制没讲。

判断「必要」的标准：删掉它，读者下一步就做不出来。**不是「它很重要」，是「删了会卡」。**

## 5. 练习站优先

有些能力是**手熟型**的：靠重复形成肌肉记忆，不需要讲原理。这类不自己造练习环境。

| 类型 | 判据 | 做法 |
| --- | --- | --- |
| **手熟型** | 知道怎么做之后，剩下的是练多少遍 | 指向成熟免费练习站，正文只给最短必要知识 + 指引 |
| **结构化型** | 不解释就做不出来，需要判据、对照表、推导 | 自己写 |

已确认的练习站（Part 0 及后续常用）：

| 站点 | 覆盖 | 免费 |
| --- | --- | --- |
| **OverTheWire: Bandit** | 终端基础到中级：`ls`/`cat`/`file`/`find`/`grep`/`sort`/`uniq`/`tr`/`base64`/`tar`/`ssh`/权限/定时任务 | 是，SSH 直连，无需注册 |
| **OverTheWire: Natas** | Web 入门（源码泄露、目录遍历、注入启蒙） | 是 |
| **picoCTF** | CTF 入门题，按方向分类 | 是，需注册 |
| **CryptoHack** | 密码学（含古典与现代） | 是，需注册 |
| **Puzzle Hunt 归档**（各年度公开 hunt） | Puzzle Hunt 真题 | 是 |

### 引用练习站时要写清的四件事

1. **打哪几关**（具体编号，不是「做完 Bandit」）；
2. **为什么是这几关**（对应本章哪个目标）；
3. **命令解释**（练习站通常只给线索，不给解释）；
4. **它缺什么**（见下）。

### 已知的缺口（所以正文要补）

- **成体系的任务流**：Bandit 是关卡式推进，每关一个孤立技巧；它没有「给一份日志，产出一份侦察报告」这种整条流程。
- **排错**：练习站几乎不教「报错在说什么」。这必须自己写。
- **中文**：所有练习站都是英文，且大量用双关与暗示。读者的英文弱，需要把提示翻成直白的话——但**不替他把关做掉**。
- **为什么**：练习站只给「怎么做」，不给「为什么是这个而不是那个」。判据与对照表必须自己写。

## 6. 复验协议

复验方是**独立子 agent**，输入只有：读者画像 + 本章正文。不给写作包、不给大纲、不给 specs。

它的任务，只有一条：

> 从头读到尾，逐节标出「**我必须跳出去查**」「**我必须猜**」「**我没法验证自己理解得对不对**」的位置。

约束：

- **不许提修改建议**。它一提建议就变成第二个作者，会把自己的写法混进来；
- 按「卡住的程度」排序，不按章节顺序；
- 允许它说「这一节我全看懂了」——那是有用的信号，说明这节达标；
- 它读不懂时**不要我解释**。它读不懂就是读者读不懂。

我拿到卡点清单后决定：改正文 / 改前置 / 改节序 / 认定可接受（并记进 `specs/`）。

**为什么必须独立**：我自己复验时，会下意识用脑内的上下文补全跳步，看不出问题。这不是能力问题，是有记忆的人必然如此。

## 7. 一页速记

```text
给：定位 / 全局大纲 / 前置清单 / 唯一目标 / 节表与实测输出 / 风格规范 /
    概念边界 / 明确不教 / 题目与考点 / 篇幅参考 / 交付格式 / 自查要求
不给：讨论史 / 旧版本 / 别章正文 / 偏好演化 / 进度元话语

三方：校验（我，有全部上下文）→ 写作（子 agent，只有写作包）→ 复验（另一个子 agent，只有正文）

篇幅是预警不是门槛：删了会卡才保留。
手熟型知识给练习站与指引，结构化知识自己写；练习站缺的四样（任务流 / 排错 / 中文 / 为什么）必须补。
```
