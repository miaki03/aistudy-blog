# 课程形态备选方案（供评审，未定稿）

> 目标读者：计科大一生。Python 弱、英文弱、每周 5–10 小时、想单人完成。
> 三线：ARG / CTF / Puzzle Hunt。写作地点：Hugo + Stack，站点 ai.xcfx.com。
> 本文件只讨论**结构**，不讨论实现。

---

## 先定两条约束

1. **教学单位必须是「闭环」，不是「知识点」**：每页要有可验证的能力点 + 自带题 + 答案。
2. **题目来源决定课程形态**。真实题目有版权与链接失效问题，自建题目有幻觉风险。两者的配比会直接改变课程长相。

---

## 方案 A：项目里程碑式（6 个项目）

以「做完 6 件事」为主线，知识在需要时插进来。

| 序 | 项目 | 时长 | 交付物 | 顺带学的 | 题目来源 |
| --- | --- | --- | --- | --- | --- |
| P0 | 工具箱装机 | 5h | 工具跑通清单 + 1 道编码题解 | 命令行、CyberChef | 自建 |
| P1 | 编码套娃 | 8h | 自制 5 层编码 + 解 10 道 | 编码、数制、位运算 | 自建 |
| P2 | 可疑文件包 | 8h | 一份取证报告 | 隐写、文件分析、取证 | 自建样本 |
| P3 | 单人 Puzzle Hunt | 10h | 完成 Puzzled Pint 一期 + 复盘 | 提取、枚举、meta | 真实档案 |
| P4 | 迷你 ARG | 10h | 自建 5 环节 + 解别人一个 | 跨媒介、线索链 | 自建 + 复盘 |
| P5 | solo 一场 CTF | 8h | 参赛 + 完整复盘 | 综合、时间分配 | 真实比赛 |
| P6 | 出 3 道题 | 6h | 3 道可解的自出题 | 反向理解 | 自建 |

- 总量：约 55h 核心 + 缓冲 ≈ 70h。
- 优点：每步有产物、动机强、天然抗拖延。
- 缺点：**覆盖不全**——古典密码、OSINT、Web 可能整条漏掉；「全面知识」这个诉求满足不了。
- 适合：目标偏「体验与作品」，不在乎体系完整。

---

## 方案 B：技能点平铺（约 48 页）

每个技能一页，全站平铺，靠目录和搜索导航。

| 组 | 页数 | 内容举例 |
| --- | --- | --- |
| 编码与数制 | 8 | 进制、位运算、base 家族、URL/HTML、摩斯/培根、Unicode 同形字、判断流程 |
| 文件与隐写 | 8 | magic bytes、binwalk、LSB、元数据、音频频谱、压缩包异常 |
| 取证与网络 | 6 | pcap、Wireshark 过滤、文件恢复、日志、HTTP 基础 |
| 密码 | 8 | 替换与词频、Vigenère、换位、RSA 识别 |
| OSINT | 5 | 搜索操作符、图片反查、地理定位、whois/wayback |
| 提取与结构 | 8 | 题型识别、12 种提取、meta、答案格式 |
| 工具与工作流 | 5 | 命令行流水线、Python 脚本化、笔记与复盘 |

- 每页：概念 800–1500 字 + 1 个演算示例 + 3 道题（1 易 1 中 1 综合，各带提示阶梯与答案）。
- 总量：约 144 道题。
- 优点：覆盖完整、可检索、进度可量化、便于长期维护。
- 缺点：**枯燥、无项目感**，正是你说不想要的「纯理论」。
- 适合：立志系统学完、能自我驱动的人。

---

## 方案 C：模块 + 小节（8 模块 → 约 40 页）

保留现有 8 个模块作顶层导航，每模块拆 4–6 节。

| 模块 | 小节数 |
| --- | --- |
| 00 学习法 | 4 |
| 01 基础底座 | 6 |
| 02 CTF | 6 |
| 03 Puzzle Hunt | 5 |
| 04 ARG | 4 |
| 05 工具与资源 | 4 |
| 06 进度与复盘 | 3 |
| 总览 | 2 |

- 优点：导航清晰、改写成本最低（现有 8 篇直接当模块首页）。
- 缺点：**本质还是「课程表」**，项目感只靠文字描述，实践没有落到交付物上。
- 适合：想快速上线、后续再迭代。

---

## 方案 D：闯关式（约 20 关）

一条 20 关的路线，每关是一道真实题目或一组，藏在一个叙事里；过关解锁下一关；卡住时才出现「补给站」讲解。

- 优点：动机最强，天然契合 ARG/Puzzle Hunt 的气质；做得好会很有传播力。
- 缺点：
  - **难度曲线必须严格单调**，否则一关卡死全站报废；
  - 单人没有队友，卡住就是停摆，必须有「跳过关卡」的逃生门；
  - 「全面知识」最难保证——剧情推着走，不会去补无关技能；
  - 设计成本最高，约等于做一个游戏。
- 适合：作为**第二期**的体验层，而不是第一期的教学主体。

---

## 方案 E：主线项目 + 补给站（推荐）

方案 A 的骨架 + 方案 B 的技能点做成「补给站」，两者用一张映射表绑定。

```
主线（6 个项目）  ←→  补给站（约 26 个技能页）
P1 编码套娃        →    进制与位运算 / base 家族 / 摩斯培根 / 判断流程
P2 可疑文件包      →    magic bytes / binwalk / LSB / 元数据 / 音频频谱 / 压缩包
P3 单人 hunt       →    题型识别 / 提取 12 法 / meta / 答案格式
P4 迷你 ARG        →    兔子洞 / 线索链 / 跨媒介 / 自建
P5 solo CTF        →    pcap / Wireshark / 文件恢复 / 古典密码 / RSA 识别
P6 出题            →    反向理解 / 好题标准 / 自测
全周期             →    命令行流水线 / Python 脚本化 / CyberChef / 笔记与复盘
```

- **覆盖率由映射表保证**：每个补给站必须被至少一个项目引用；没被引用的要么删掉，要么补一个项目去用它。
- 每页仍自带 3 道题与答案（可机器验证优先）。
- 总量：6 个项目页 + 26 个补给站 ≈ 32 页。
- 优点：项目驱动 + 覆盖可查 + 导航清晰。
- 缺点：映射表要维护；项目页与补给站之间需要明确的「什么时候跳到哪一页」的提示。

## 题目来源策略（需要单独讨论）

你的判断我同意：复杂题目 AI 出不好，真实题目更可靠。但「爬题」有两个坑：

1. **版权**：Puzzle Hunt 题面版权归作者，多数 hunt 允许引用与转载但要求署名；ARG 素材多已下线。
2. **链接失效**：档案站相对稳定（MIT Mystery Hunt 官网、Puzzled Pint 官网），但单题链接会随改版漂移。

建议的可持续做法：

| 做法 | 说明 |
| --- | --- |
| **不转载题面，只链接 + 自写解法** | 绕过版权，且解法比题面更有教学价值 |
| **自建同型练习** | 编码/隐写/取证类都能用真实数据生成，可控可验证 |
| **真实题只做「实战项目」** | P3/P5 用真实档案与比赛，其余用自建 |
| **自建题必须机器可验证** | 有唯一答案、有校验脚本，杜绝幻觉 |

如果接受这个策略，则课程里「题」的来源大致是：自建 70%、真实档案 30%，并且真实题目全部以「项目 / 实战」形式出现，而不是散在知识点里。

---

## 我的建议

选 **方案 E**，理由：它是唯一同时满足「项目驱动」「覆盖可查」「单页轻」的形态，而且现有 8 篇文章可以降级为「模块导语」，不浪费。

是否要做方案 D 的闯关层，可以留到第二期：等 26 个补给站都稳定了，把其中一部分串成一条闯关线，成本就低很多。
