## 04 · ARG 解剖：线索链、跨媒介与自建

> 覆盖 W10–W11（主攻）+ W12（综合创作）。本模块是三条线里**资源最不可控**的一条：真实 ARG 是限时社群活动，档案大多不可复现。所以这里的做法不是「做题库」，而是**精读案例 → 复刻单个环节 → 自建 mini ARG**。

---

## 1. 本模块目标

- [ ] 能说出 ARG 区别于「谜题合集」的三个特征
- [ ] 能拆解 2 个经典 ARG 的线索链（画成图）
- [ ] 能独立完成 4 项跨媒介提取（频谱、条码、社交、域名）
- [ ] 能设计并自测一个 5 环节的 mini ARG
- [ ] 知道单人玩 ARG 的现实边界在哪

---

## 2. ARG 是什么

**Alternate Reality Game（另类实境游戏）**：以现实世界（或伪装成现实的网络世界）为舞台、由设计师（puppet master）暗中操控、玩家通过线索链推进的叙事型解谜。

### 三个判别性特征（缺一个就不是典型 ARG）

| 特征 | 含义 | 例 |
| --- | --- | --- |
| **兔子洞**（rabbit hole） | 有个伪装成正常内容的入口，不告诉你「这是游戏」 | 一个假公司的官网、一条可疑推文 |
| **跨媒介** | 线索分散在网页、音频、视频、电话、邮件、实体之间 | 视频里一闪而过的网址 → 网站源码里的密码 |
| **实时/社群** | 随玩家进度动态更新，靠社群协作 | 设计师根据玩家行为解锁下一阶段 |

### 为什么单人玩 ARG 很难（先认清）

| 难点 | 原因 | 本路径的对策 |
| --- | --- | --- |
| 活动是一次性的 | 线索链依赖线上资产，活动结束就下线 | 只做**案例精读**（看复盘与档案） |
| 靠社群推进 | 单人速度慢，谜题设计默认多人并行 | 只做**环节复刻**，不做全流程 |
| 现实元素 | 线下地点、实体物品 | 跳过 |
| 没有「题库」 | 无法像 picoCTF 那样刷题 | 用**自建 mini ARG** 反向理解 |

> 所以本模块的产出不是「通关数」，而是「你看懂了一个 ARG 是怎么被设计出来的」。

## 3. 解剖结构（拆任何一个 ARG 都用这张图）

```
玩家世界                          设计师世界
────────────────────────────────────────────────
兔子洞入口  ←── 伪装 ──  一个"看起来正常"的资产（假网站/假账号）
    │
线索 A（网站里的隐藏文件）──┐
线索 B（音频频谱里的文字）──┤── 线索链（trail）：一串互相指向的谜题
线索 C（社交账号的时间线）──┘
    │
门禁（gate）：解出 A 才拿到 B 的入口
    │
叙事推进：角色发消息、网站更新、剧情分支
    │
终局（或无限期悬置）
```

**拆解时逐项记录**

1. 入口是什么？伪装成什么？
2. 一共几条线索链？每条链上有几个环节？
3. 哪些环节是「门禁」（必须按顺序）？哪些是「并行支线」？
4. 用了哪些媒介？媒介之间怎么跳转？
5. 有没有社群协作点（需要多人同时做的）？
6. 叙事与谜题怎么绑定？（好的 ARG，谜题本身就是叙事）

## 4. 跨媒介载体清单（提取方法按载体分）

| 载体 | 藏法 | 提取工具 |
| --- | --- | --- |
| 网页 | 源码注释、隐藏 div、robots.txt、favicon、CSS 里的 base64 | DevTools、`curl`、CyberChef |
| 图片 | 元数据、LSB、附加数据、二维码、频谱 | exiftool、zsteg、binwalk、CyberChef |
| 音频 | 频谱图形、反向播放、摩斯、DTMF、隐含人声 | Audacity、sonic-visualiser、sox |
| 视频 | 单帧闪现、字幕轨、音轨分离、帧顺序 | ffmpeg（`-vf fps=1` 抽帧） |
| 社交 | 时间线首字母、发帖时间戳、图片拼接、@关系 | 手工 + 截图 + 表格 |
| 域名/网络 | whois 注册人、子域、Wayback 旧版、DNS TXT | whois、Wayback Machine、dig |
| 文档 | docx/zip 内部、PDF 对象、隐藏文字 | 解压、`pdftotext`、CyberChef |
| 电话/邮件 | 语音信箱、自动回复、号码编码 | 手动（单人成本高，选做） |

> **单人优先做前 6 类**，后 2 类知道原理即可。

## 5. 经典案例库（W10 精读 2 个即可）

| 案例 | 年份 | 为什么值得看 | 观察重点 |
| --- | --- | --- | --- |
| **The Beast** | 2001 | 公认最早的商业 ARG 之一（电影《人工智能》宣传） | 兔子洞如何伪装成"官方宣传" |
| **I Love Bees** | 2004 | 规模最大的早期 ARG 之一（《光环 2》宣传），含音频/电话/线下 | 跨媒介跳转与社群协作点 |
| **Why So Serious** | 2007 | 《黑暗骑士》宣传，含大量线下实物 | 现实世界如何被纳入线索链 |
| **Year Zero** | 2007 | Nine Inch Nails 专辑配套，叙事极强 | 谜题与叙事的绑定方式 |
| **Perplex City** | 2005 | 付费解谜游戏，含实体卡片与线下寻宝 | 长期运营的谜题经济 |
| **Cicada 3301** | 2012 起 | 匿名谜题，隐写/密码/书籍/暗网，至今有未解部分 | 纯技术的线索链如何设计 |

**精读方法**（2 小时/案例）

1. 先看一份**事后复盘**（recap），不要看逐题攻略。
2. 画出线索链图（用纸或 draw.io）：入口 → 环节 → 门禁 → 分支。
3. 标出「哪些环节我单人做不了」，并写下原因。
4. 写 5 行中文摘要：结构 / 跨媒介点 / 我最想复刻的一个环节。

> 中文复盘稀缺（已挂进 [总览的「资料补给机制」](/p/learning-path/)）。英文复盘优先看 ARGNet 的归档与社区 Wiki。

## 6. 单人可做的三类练习

### 练习 A：案例精读（W10）

产出：2 张线索链图 + 2 份 5 行摘要。
判据：能对别人讲清「这个 ARG 的第 3 个环节为什么必须解完第 2 个才能进」。

### 练习 B：环节复刻（W11，做 4 个）

从 §4 的载体里挑 4 个，各做一个「自己藏、自己挖」的小闭环：

| # | 任务 | 验收 |
| --- | --- | --- |
| 1 | 在一张图片里用 LSB 藏一句话，再写脚本提取 | 提取脚本能跑通 |
| 2 | 在一段音频里用频谱藏一段文字 | 频谱截图能看出文字 |
| 3 | 用 GitHub Pages（或本地 HTML）做一个「假公司官网」，源码里藏第 1 步线索 | 自己按线索走通 3 步 |
| 4 | 用 Wayback Machine 找任意网站的旧版，从差异里找出 1 条信息 | 写出「我是怎么找到的」 |

### 练习 C：自建 mini ARG（W12）

**最小可行结构（5 个环节，单人 2–4 小时可完成）**

```
环节 1：一个本地 HTML 页面（伪装成某个"公司"官网），源码注释里藏 base64
   → 解出：一个词（作为下一步的"门票"）
环节 2：一个图片文件，元数据里藏"下一步的文件名"
   → 解出：文件名
环节 3：一个音频文件，频谱里藏一句话
   → 解出：一句话（作为密码）
环节 4：一个加密压缩包（密码来自环节 3），里面是一段"角色日志"
   → 解出：日志里提到的一个地点/数字
环节 5：一个"终局"页面，把前面所有答案按顺序输入
   → 解出：最终答案
```

**设计纪律**
- 每个环节只考**一个**技能（不要一题三解）。
- 必须有**明确的指向**（上一环节要留下下一步的线索，而不是让玩家瞎猜）。
- 叙事要连贯：哪怕是假公司，也要让「为什么这里有这个文件」说得通。
- 自测：隔一天自己做一遍；若自己都需要回忆才知道下一步，说明线索不明确。

## 10. 常见卡点

| 卡点 | 真相 | 处理 |
| --- | --- | --- |
| 找不到完整 ARG 档案 | 大部分已下线 | 只看复盘与 Wiki，不做全流程 |
| 案例复盘看不懂 | 缺背景 | 先看维基百科条目建立背景，再看复盘 |
| 复刻练习太简单 | 正常，这是练工具手感 | 提高难度：多加一层编码 |
| 自建 ARG 变成"拼题" | 缺叙事 | 先写 5 行故事，再把环节嵌进去 |
| 想复刻大型 ARG | 单人做不到 | 只复刻**一个环节**，别复刻整个活动 |
